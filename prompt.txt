12. PERMANENT BUY-ONCE RULE
==================================================
After one confirmed successful purchase of a token mint, the bot must never buy the same mint again.
This remains true after:
Selling
Application restart
Server restart
Cache clear
Deployment
Database reconnect
Bot stop/start
Strategy change
PostgreSQL is the permanent source of truth.
Table:
purchased_tokens
Fields:
mint_address PRIMARY KEY
creator_address
first_detected_at
first_buy_submitted_at
first_buy_confirmed_at
buy_signature
entry_price
entry_market_cap
strategy_version
exit_signature
exit_price
final_pnl_percent
final_pnl_sol
created_at
updated_at
Load purchased mint addresses into memory during startup.
Use a Rust HashSet or DashMap for the fast lookup.
Use Dragonfly SET NX for distributed reservation.
Use PostgreSQL unique constraint as final protection.
Flow:
token detected
↓
RAM check
↓
distributed reservation
↓
PostgreSQL protection
↓
strategy decision
↓
buy
A confirmed purchase permanently adds the mint to the registry.
A failed submission with no on-chain fill does not permanently blacklist the token.
