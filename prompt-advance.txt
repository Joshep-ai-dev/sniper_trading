13. PERMANENT BUY-ONCE RULE
==================================================

After one confirmed successful purchase of a token mint, the bot must never buy the same mint again.

This remains true after:

Selling

Application restart

Server restart

Machine restart

Cache rebuild

Deployment

Database reopen

Bot stop/start

Strategy change

RocksDB is the permanent source of truth.

Use column family:

purchased_tokens

mint_address

Stored record:

creator_address

buy_signature

entry_price

entry_market_cap

strategy_version

exit_signature

exit_price

final_pnl_percent

final_pnl_sol

created_at

updated_at

Load purchased mint addresses into RAM during startup.

Use:

HashSet

or

DashMap

for fast lookup.

Use an in-process pending reservation map.

Use RocksDB durable reservation as final local protection.

Flow:

token detected
↓
RAM purchased check
↓
RAM pending check
↓
atomic pending reservation
↓
RocksDB durable reservation
↓
strategy decision
↓
buy
↓
transaction confirmation
↓
RocksDB permanent purchased record
↓
RAM permanent registry update

A confirmed purchase permanently adds the mint to the registry.

A failed submission with proven no on-chain fill does not permanently blacklist the token.

If purchase status is uncertain:

mark UNKNOWN_PENDING

keep mint blocked

reconcile blockchain state

do not submit another buy until resolved
